# SlopTogether — acceptance and verification specification

Current evidence is recorded in the [October 24 audit](../../docs/implementation-audit-2026-10-24.md); ordered exit checks are in the [completion plan](sloptogether-completion-plan.md). A four-clip smoke does not satisfy continuous-stream acceptance: verify sustained queue refill, append without reload, recovery and bounded resource use with no clip-count cap.

Status: planned gates for future implementation, updated with [the user's confirmed scope](../../docs/product-decisions.md): complete public app, Windows generation/upscale choices, approximately 15-second16:9 browser output captured in standard OBS, single paid attempts and configurable trusted approval. These are acceptance requirements, not claims that the app already exists.

## Source import evidence (completed)

See `docs/worker-import.md` and `vendor/comfystream/import-manifest.json` for source identities and commands. Reported offline results: exact assembler check passed; 20 existing CPU tests passed with one unrelated host deployment test deselected; 181 Python modules parsed; 367 relative imports resolved; 295 recorded file digests matched. No GPU, fal deployment, installer or Windows/4090 qualification was run.

## Unit and database invariants

| ID | Case and expected result |
|---|---|
| T01 — Channel isolation | A user/mod/device authorized in channel A cannot read private B inputs, vote as B, obtain B uploads, accept B jobs, approve B media or move B's playhead, including guessed IDs and realtime filters. |
| T02 — Shared boundaries | Selecting/editing boundary B(i+1) updates both dependent mutable segment references atomically; locked/published neighbor mutation fails or creates a fork with valid entry/rejoin transitions. A changed start image cannot attach directly to a mismatching unchanged predecessor. |
| T03 — Lock concurrency | Race two vote closures/manual locks/payment intents against one target; one revision wins. No two mutually incompatible accepted selections. |
| T04 — Ballots | Twitch Extension and chat are both voting clients of the same API/election. Same verified Twitch user has one active free ballot across Extension/chat/website; changes before deadline replace it. Late/closed/streamer-overridden election rejects further votes and all surfaces reflect authoritative state. Native poll totals use an explicit separate counting mode. |
| T05 — Dependency invalidation | Changing requested prompt/frame/seed/provider produces a new input digest; old results cannot complete the new stage or reuse approval. Accepting an artifact-derived endpoint resolution does not change its own producing job's input digest. Replacing that accepted source resolution fences dependent jobs/resolutions/approvals; published history remains immutable. |
| T06 — Temporal arithmetic | Approximately15-second native362/24 clips and configured15-second Turbo outputs accumulate measured PTS without `index*15` drift; no forced truncation to exactly 15.000 seconds that discards endpoints. |
| T07 — Dimensions | Native448×256 to1162×664 upscale accepted; direct1184×666 rejected by the inspected SoL contract. Final publication is exactly16:9 (initial 1280×720) with consistent fit/pad, no stretching and stored shared-boundary transforms. Native7:4 intermediates cannot be published as the final output. |
| T08 — Stage identity | Upscale leases bind exact accepted base digest; cannot use another user's URL or a superseded base. Different render/upscale byte output invalidates its own final approval. |
| T09 — Fencing | Old heartbeat/completion/upload refresh fails after lease reclamation, absolute attempt deadline, cancellation, worker ban or channel revocation. Donor replacement increments the fence; a cancelled remote GPU result cannot revive the job. Managed-provider uncertainty remains held/reconciled instead of blindly redispatched. |
| T10 — Idempotency | Duplicate event, claim retry, completion retry or outbox delivery produces one accepted effect; no double vote, publication or paid fulfillment. |
| T11 — Unknown submit | Timeout after provider accepts leaves UNCERTAIN; a known remote ID or supported client key reconciles the attempt. Unknown remote ID without lookup capability holds the attempt/reserved spend for operator reconciliation; no blind duplicate submission or false recovery claim. |
| T12 — Budget | Concurrent reservations cannot exceed channel/global caps; uncertain attempts retain a reservation; spent actuals and released reservations reconcile. |
| T13 — Controller | Only current output lease/epoch moves source position; viewer preview cannot. Out-of-order heartbeat or another stale browser seek is rejected. |
| T14 — Approval binding | Input screening alone does not admit output; exact hash receives human approval or explicit current trusted-system policy approval. Public untrusted output cannot claim the trusted path. New bytes/untrusted upscale require their own decision; unrelated contributor/reviewer membership grants no upload bypass. |
| T15 — Publication | Upload/validation alone cannot expose public artifacts. Manifest commits reference only approved immutable objects; late upscale cannot change an already committed buffer. |
| T16 — Continuation resolution | Dispatch with null requested end and immutable input digest; accept a validated/moderated source artifact and separate resolved end; producer remains current. Successor consumes the accepted resolution ID. Race endpoint acceptance/replacement: one current resolution wins; source replacement fences its affected descendants. An upscale cannot redefine that endpoint. |
| T17 — Fork joins | Fork at an unchanged future boundary outside protected buffer, regenerate incoming transition for changed anchor, and rejoin a suffix only at its exact boundary revision or through a generated outgoing bridge. Verify both joins; mismatches reject seamless switching. Explicit discontinuous cut emits playback/manifest discontinuity. Original branch/publication/paid target stays unchanged. |
| T18 — Lease lifetime and quotas | Heartbeat expiry is capped by server-owned absolute deadline, including upload grace. Across many devices the same Twitch account cannot exceed two active attempts globally/two per channel or one per worker slot. Three nonproductive expiries in24 hours enforce the configured cooldown. Claims that cannot meet result deadline are rejected. |
| T19 — Single paid attempt | Concurrent regenerate/job/outbox requests on the same payment, including a changed/reopened slot revision, obtain at most one billable dispatch authorization. Rejection/failure/uncertain acceptance never restores it. Same-request result/transfer recovery creates no new render; a new owner-funded refill uses its own reservation. |
| T20 — Rejected slot | Reject selected unplayed candidate: preserve spent payment/artifact audit, retire selection, fence old result/leases and dependent resolutions, then create a fresh OPEN slot/election revision with valid neighbor anchors. Another eligible contributor/vote can fill it; late old completion cannot. |
| T21 — Independent channel policies | Public/role/allowlist contribution, reviewer list, upload bypass, trusted worker keys and streamer-control grants are independent. Ordinary grants cannot mint stronger keys or override votes. A verified broadcaster/full-control key may authoritatively edit/unban/review its own channel; changed/revoked issuer authority invalidates derived credentials. |
| T22 — Exact input screen | Prompt/normalized image hashes bind model/policy evidence. Rewrites/new boundaries require fresh clearance. Flagged/missing evidence cannot authorize ordinary generation; only an explicit permitted streamer-control review can resolve a hold, preserving the original classifier result and separate scoped decision. Trusted worker status alone does not clear it. |
| T23 — Authoritative override | Streamer OAuth/full-control key replaces a voted/locked future range while jobs/uploads are active: new input/selection/producer epochs fence old results, valid bridges or explicit cuts preserve playback semantics, automatic writers respect the override hold, and spent viewer payments stay consumed. New render gets new funding. |
| T24 — Scoped channel keys | High-entropy worker/controller key verifier and issuer/channel/scopes are server-owned. Wrong-channel/expired/revoked/rotated key and derived session fail; ordinary worker cannot self-upgrade. Lease admission serializes on the active execution binding so a concurrent key revocation either fences the admitted lease or prevents its claim. Headless key auth uses issuer identity rather than demanding interactive Twitch login on each fal boot; secrets stay out of images/URLs/logs. |
| T25 — One story producer | Two instances of the same program contend for channel story-producer authority: one current lease/fence and one unexpired per-attempt claim token win; a parallel claim returns empty. Claim expiry allows recovery with the same idempotency key and scene seed. Duplicate/stale submissions fail. A subscriber-interrupt plan cannot be submitted as an ordinary story or rebound to another interrupt. Streamer takeover fences it and stale writes cannot restore overridden content. |
| T26 — Subscription event identity | Disabled channel never creates an alert job. Repeated verified receipt creates one interrupt/plan/render identity; aggregate-gift mode ignores recipient is_gift subscribe notifications, respects anonymous gifts and does not treat subscription-end events as new subs. Resub mode reacts to the configured shared-message event, not an invented renewal signal. |
| T27 — Interrupt program mapping | An interstitial is separate from story/paid slots: save resume source and controller epoch, append eligible program span with explicit discontinuity, advance program time while story cursor pauses, then resume current authority. Streamer seek/override cancels stale auto-resume. No decoded HLS prefix is rewritten. |
| T28 — Cheap H3 planning | Structured scene output compiles through the inspected H3 formatter, plain dialogue<=30 words, valid speaker IDs and reserved-markup rejection. Bounded call/token/spend limits and template fallback prevent repair loops; names/messages cannot set instructions/IDs/budgets. Final compiled prompt/images get clearance; text/image moderation is not a full audio/video check. |
| T29 — Comfy Cloud start frame | Only a signed-in broadcaster for a server-allowlisted channel may submit a frame job; the explicit credit notice precedes submission, prompt screening must clear, and one local idempotency request maps to at most one Comfy Cloud job. Enforce one active/uncertain job for the shared account plus the per-channel and app-account hourly caps. An ambiguous submit becomes uncertain, blocks another request, and cannot auto-resubmit. Polling resumes after reload, cancellation is surfaced, provider assets remain private, and exact output bytes pass image moderation before download and normal proposal upload. The frame is cropped to the pinned 448×256 H3 input profile. After seven days, a leased outbox event deletes its stored prompt and job reference.
| T30 — Comfy Cloud prompt suggestion | Only an authenticated broadcaster on an allowlisted channel can request a prompt suggestion. Screen the brief before spending, use the pinned OpenAI Chat/SaveText workflow, validate the exact H3-compatible format and moderate the generated text before returning it. The UI fills an editable draft without submitting a proposal. The provider credential stays server-side; one active/uncertain request and shared account rate caps apply; ambiguous submission never retries. |

## End-to-end product acceptance

1. **Public Twitch loop:** a public eligible viewer signs in/links identity, proposes for an upcoming slot, exact input preflight clears, chat/site/extension selects, trusted managed worker renders and system-approves valid media, and it plays in the 16:9 browser window captured by OBS. Repeat with an ordinary Windows donor: clip stays private until a permitted reviewer approves. Demonstration evidence alone does not replace the public application release gate.
2. **Continuity:** render three connected slots with shared anchors; compare decoded transitions after trusted conformance. Record source/published timings, endpoint tolerance and manual visual assessment. In continuation mode prove requested end stays null and original digest stays unchanged after separate output resolution; successor uses that resolution. Replace the accepted source and prove descendant fencing. Exercise independently rendered planned-anchor mode too.
3. **Independent Windows compute:** contributor A selects generation only and B selects upscale only, both Twitch-connected in Windows clients; jobs upload through authenticated Cloudflare flow. Each stage retains provenance and uses its producer's human/trusted approval path. Both choices must work on qualified4090 recipes; showing only one role is partial completion.
4. **Ten-minute edit:** choose a future slot, conflict with an adjacent locked anchor, fork at an earlier unchanged eligible boundary and regenerate incoming transition; regenerate outgoing bridge or match exact suffix boundary before rejoining. Check both visible joins and prove old completion cannot land on the new branch. If protected history prevents a seamless fork, require a later edit or an explicit discontinuous seek, not an implicit cut.
5. **Playback controls:** play, pause, seek backward, skip forward, preview privately, reconnect and transfer controller; only authorized source output changes the live marker. Historical events reflect replay correctly.
6. **Reject/reopen and stall:** reject a paid candidate, verify consumed payment remains unusable and a fresh contributor/election can fill the reopened slot. Trusted automatic refill needs new owner/channel funding. Disconnect donors or block a new prompt preflight: cleared work may continue, otherwise safe fallback/hold preserves the browser source without unbounded spending.
7. **Restart:** restart coordinator mid-provider-submit, mid-upload, mid-validation and after committed publication; no duplicate accepted spend/result and no unapproved HLS.
8. **Continuous fresh-output gate:** run at least60 minutes at1x browser playback under declared worker/profile/trust policy, starting with180s contiguous playable buffer. Allow final buffer>=540s plus batching tolerance (initial high-water600s). Exclude primed/precomputed video beyond that starting buffer; required video stages execute during observation. Produce>=3960 fresh contiguous selected-branch playable seconds/hour and>=900 per consecutive15-minute interval, maintain>=120s buffer and final>=initial. Exclude replay/filler/rejected/speculative/duplicate variants. The trusted mode uses input preflight+media validation+system approval without human-per-clip waits; separately test public donor queues with their actual reviewer/bypass configuration. Record PTS, rates, buffer, costs/rejections, preflight health and approval paths. Failure downgrades the measured throughput claim to buffered mode; it does not waive the complete public-product requirement. Test false passes from prebuffer, timeline gaps, duplicate upscale counts and improper high-water throttling.
9. **Public complete release:** production `/sloptogether` route, public channel-policy modes, working signed Windows generation/upscale downloads, Twitch connection/bans, quick input screening, trusted continuous approval, manual donor review, one-paid-attempt/reopen and clean 16:9 OBS capture all work end to end. Apply actual Bits eligibility/approval on monetized channels. A private demo or role-limited client cannot pass this gate.
10. **Optional subscriber mode:** with the setting enabled, a verified subscription produces one bounded, funny H3 dialogue alert; the ready clip interrupts and resumes browser-captured story without changing a paid contribution. Repeat with gifts/resub policy, already-buffered story, streamer override and event/worker restart. With it disabled, no event-driven story/video spend occurs.

## Hardware and desktop qualification

Matrix: actual Windows x64 RTX4090/24GB for both user role choices and the shared program's Linux/fal headless build on exact GPU/driver/container variants. Both runtimes are required and independently qualified; cloud96GB success does not establish Windows24GB support. An additional polished Linux desktop UI is not required.

- Clean install, signature validation, model/license prompt, cache integrity, driver mismatch behavior, pause/restart, safe update/rollback and uninstall.
- First-run model load plus20 sequential representative jobs; generation-only, upscale-only, role switch, reference-heavy/boundary/audio cases within allowed bounds, retry and OOM injection.
- Capture NVML device/process peak, Torch allocated/reserved peak by phase, host RAM/pinned memory, disk/cache growth, GPU utilization/temperature and per-stage/cold/warm timings.
- Initial peak target 21.5GiB on an otherwise idle 24GiB GPU, dynamically restricted by available memory; reserved display/OS headroom and user-configured budget enforced. No OOM or monotonic memory growth across qualified run.
- Reject SM120/NVFP4/MXFP8 profiles on SM89; test actual safe attention path without giant dense-mask fallback. Do not infer quality from a successful allocation.
- Compare accepted output quality/continuity for portable precision/offload against trusted baseline, with recorded defects and latency tradeoffs. No promise every volunteer is faster than real time.
- Confirm no simultaneous heavy generation+SoL model residency on a single GPU, bounded decoded-frame buffers and clean unload between roles.

## clips.gg deployment regression and rollback

Verify child directly and through a host preview before any production route change:

- Exact `/sloptogether`, nested channel/moderation routes, assets, APIs, OAuth callback and query handling keep the prefix; similar `/sloptogether-evil` is not bypassed.
- Landing-only host mode still serves child path and preserves all existing behavior elsewhere. `api.clips.gg` guard remains effective. Child API enforces its own auth.
- Existing ClipsGG homepage/login/callback/tasks/admin/billing/Reddit contracts and cron configuration remain unchanged; run existing relevant host checks in an isolated integration branch.
- Unique child cookie and no root-scope service worker; actual child-origin request capture proves `clipsgg-sb-auth`/host identity headers absent; child response cookies are allowlisted names/path with no host-cookie overwrite. No leaked provider secrets; main-origin UGC XSS/redirect tests; shared-origin residual risk recorded.
- Worker uploads go directly to a bounded Cloudflare upload service, not through a Vercel body-size bottleneck. Realtime subscriptions use dedicated service and channel policies.
- Disable both child rewrites and middleware bypass together; confirm host behavior restored while SlopTogether data remains isolated. No source/host dirty edits lost.

## Completion claims

Application features are complete only when their corresponding real behavior passes, not when mocked schemas or static references exist. Planning completion means source import is inspectable, requirements and open decisions are captured, evidence is linked, limitations are explicit, and a separate reviewer has checked the plan. Deployment, paid approval and GPU compatibility stay unclaimed until their gates pass.
