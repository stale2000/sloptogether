## Engineering and external qualification still needed

- **Shared Windows/Linux worker qualification:** an Ada FP8 plus sequential-offload SoL upscale candidate now passes a 24 GB VRAM / 128 GiB system RAM gate, while large Blackwell cards retain resident NVFP4. FastH3 defaults to fixed Kitchen VSA for local/WSL workers and opts into adaptive VC only from the Fal generation image pinned to `GPU-RTXPRO6000`; the worker no longer infers ComfyUI's selected GPU from its separate process. A Windows client can now pair as `wsl`, connect to a WSL2 ComfyUI backend and use the shared Linux recipes. Native Windows inference is still rejected. The WSL2 path remains unqualified: no Windows RTX 4090 load/inference, output quality, latency or continuity test has run, and pairing's platform claim is not hardware attestation. Both WSL2 roles still need hardware qualification and a signed supported installation path before release.
- **Windows node/runtime installation:** The WSL2 setup bundle offers pinned runtime, node and model installation options. Clean-machine Windows execution, resumability, signing and actual RTX 4090 qualification remain unverified; see the [completion plan](completion-plan-2026-10-27.md).
- **Prompt/image-check latency and capacity (Q22):** the web and media publisher accept the dedicated `SLOPTOGETHER_OPENAI_MODERATION_KEY` for free text/image screening, separate from the paid owner story-planning key; unit tests cover clear, held and missing-key fail-closed cases. Production now has its own moderation credential and health reports the preflight as configured. Real prompt/image screening latency, capacity and outage behavior under channel traffic remain unmeasured; missing/unavailable screening must keep new unchecked work pending rather than bypassing checks.
- **Subscriber-interrupt qualification:** EventSub admission, owner story planning, screened single-attempt generation, HLS item publication and safe-boundary seek/resume are implemented. Still measure actual EventSub delivery, owner-worker latency/cost, audio preservation, HLS buffer seeking and resume behavior; provide reconciliation for text-planner token costs and qualify cancellation races on a live database/browser.
- **Visible boundary tolerance (Q30):** shared endpoint identity/fork rules are fixed; measure acceptable actual generated/conformed endpoint deviation and visual transitions for each recipe.
- **Distribution rights (Q31):** retain worker MIT/third-party notices, verify model terms before signed public Windows distribution, and resolve the ClipsGG reference snapshot's empty license file before redistribution of that code.
- **Storage implementation (Q27):** R2/private uploads and trusted publication remain the baseline. Adopt Cloudflare Stream only if measured playback/operating advantages justify its separate costs; it is not required for a website-hosted Twitch broadcast, which is outside scope.
- **Public mount qualification (Q28):** requested `/sloptogether` path is fixed. Prove host-cookie filtering, independent data/secrets and rollback, and retain the documented shared-browser-origin limitation.
- **Public release gates:** complete the application, both Windows role choices, channel permission/approval settings, trusted automation, single-attempt paid integration and browser output. Provider/Extension approval and actual deployment status must be reported honestly; a demo alone cannot close the objective.
