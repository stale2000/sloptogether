# Confirmed product decisions

Recorded October 23, 2026 from the user's answers. These replace earlier proposed defaults wherever those conflict. Scope is the public app at **https://clips.gg/sloptogether**; recording decisions is not implementation or deployment evidence.

| Area | Confirmed requirement |
|---|---|
| Stream source | Video plays in the streamer's ordinary browser window, which OBS captures. Provide a clean output view and separate controls. No OBS plugin/extension and no website-operated Twitch broadcast/RTMP egress or stream-key storage. |
| Duration | Clips are approximately 15 seconds. Preserve actual native timing rather than forcing exactly 15.000 seconds. |
| Aspect ratio | Final public video/output is16:9. Generation/upscale internals can use required native shapes; trusted conformance fits/pads them consistently into 16:9, without stretching. |
| Paid generation | One payment buys one billable generation attempt. Rejection does not restore money/credits or provide another render; retire that candidate and reopen the slot for another contributor or vote. New billable work requires new payment or an independently funded owner/channel attempt. |
| Worker roles | Users choose clip generation or upscale in the local executable; manual and continuous work follow available eligible tasks. Both choices belong to requested public scope. |
| Worker program/platforms | One shared worker program/engine/job protocol, packaged as a Windows executable and Linux/headless/fal runtime. The owner's two fal workers run that same program, one for generation and one for upscale. Builds/dependencies vary by platform/GPU; the Windows RTX4090/24GB target remains. |
| Worker identity | Ordinary users connect Twitch and receive revocable device credentials. Headless owner/streamer workers can instead configure a special scoped key issued by their Twitch-authenticated channel owner. Identity/trust comes from server key metadata, not a caller flag or interactive OAuth on every fal startup. |
| Contribution settings | A channel can permit any Twitch-authenticated non-banned person, broadcaster/moderator roles only, an explicit whitelist, or a configured combination by capability. Public site access does not itself grant generation spending or upload authority. |
| Twitch participation | Viewers can submit scene-prompt proposals through the site or Twitch Extension, subject to the channel's contributor policy and input screening. They can vote through the Extension, site, or chat. All surfaces use the same channel election/API and one identified free ballot; changing surfaces does not duplicate a vote. Streamer overrides remain authoritative and visible in each client. This Twitch Extension is separate from any OBS plugin, which is not needed. |
| Subscriber shout-outs | Optional channel setting receives subscription EventSub notifications and generates a personalized approximately 10-second interstitial, then resumes the story. Spoken dialogue is required for this feature; gift/resub handling, ready-time insertion, costs and cooldown are configured and streamer-overridable. |
| Cheap story generators | Ordinary story adapters and subscriber planners emit bounded H3-compatible visual prompts, short dialogue/speaker/audio fields, with one small-model call or safe template fallback. Reuse the existing prompt format and cap actual planning/render spend. |
| Review authority | Streamer/broadcaster, verified moderators and specifically whitelisted reviewer Twitch accounts can approve/reject according to channel grants. |
| Uploaded clip approval | Ordinary user-uploaded generated/upscaled media requires approval. Channel settings can explicitly whitelist streamer/moderator roles and designated uploaders to bypass human approval; contributor/reviewer membership alone is not that bypass. |
| Trusted continuous workers | Server-registered app-owner fal/operator workers are trusted. With cleared prompt/images and valid media they can continuously generate/upscale and receive automated policy approval, without human clicks per clip. No caller may self-assign trusted status. |
| Initial continuous story feed | The owner's test story generator feeds the channel through the same worker/API interfaces; it can be an adapter/mode of the shared program. Key-authorized Linux/fal workers continuously claim generation/upscale work and update future content. A separate mandatory process that invokes two different worker implementations is not required. |
| Streamer override | Streamer OAuth or a streamer-control key has full channel editorial control: override votes/locks, replace future prompts/frames/choices, stop or supersede jobs, approve/reject/hold and control source playback. Apply overrides atomically with fences/revisions and audit; new billable work uses new funding and historical payment/broadcast records remain accurate. |
| Basic moderation | Run a fast automated check on the exact prompt and actual image inputs. Use OpenAI's currently free text/image moderation endpoint when available. Held/unchecked inputs cannot trigger billable generation; unrelated already-cleared work can continue. |
| Public completeness | Build and deploy the whole requested application publicly. A hackathon demonstration or private/partial client does not complete the scope. Real GPU, payment-provider/Extension and public deployment gates still require evidence. |

Contribution eligibility, permission to review, upload-approval bypass and managed execution trust are independent settings. Bans/revocations override their grants. Automatic approval still records exact asset/input digests and policy authority and does not bypass upload/media integrity, budget, timeline or known-blocking-flag checks. Full rules: [moderation and trust](moderation-and-trust.md).

Streamer control is an explicit channel-owner authority above ordinary contribution/voting/review settings. A worker key can receive that control only if deliberately granted; a basic trusted worker key does not imply it. A streamer can explicitly resolve a channel input hold through an audited review decision, preserving automated evidence. Key lifecycle and override semantics are in [unified worker and streamer control](unified-worker-and-streamer-control.md).

Earlier review fixes remain settled: separate requested/resolved endpoints; regenerate fork joins or label a cut; measure sustained playable throughput; bound donor leases and account claims. The new trust policy changes who must manually approve a clip, not those consistency rules.

Remaining unresolved prices, audio, funding/retention and qualification details are in [open questions](open-questions.md). The free moderation fact is supported by [OpenAI's official guide](https://developers.openai.com/api/docs/guides/moderation); it classifies text/images, not complete video/audio, and service rate limits/availability still apply.
