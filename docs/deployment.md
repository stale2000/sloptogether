# Deployment requirements

Current deployment blockers and priorities are in the [remaining-work plan](../.omx/plans/sloptogether-remaining-work.md) and [implementation audit](implementation-audit-2026-10-24.md). The public Clips.gg mount and gated four-clip playback smoke are deployed. Production health sees the database, R2 configuration, moderation key and Twitch OAuth app credentials; there is still no database-backed channel, actual Twitch user session, tested R2 upload/publication, or SlopTogether Fal worker.

SlopTogether is a separate Next.js app with `basePath: "/sloptogether"`. Keep it in a separate deployment, with its own storage bucket, Twitch app/Extension secrets and provider keys. It shares the existing Clips.gg Postgres project only through the isolated `sloptogether` schema; migrations `001` through `019` never alter Clips.gg's `public` tables. Use a SlopTogether-only database role restricted to that schema. Mount the app at `https://www.clips.gg/sloptogether` through a narrowly scoped host proxy/rewrite; the apex host redirects to `www`. Do not change Clips.gg root auth cookies, routes or Vercel cron jobs.

## Configuration

1. Deploy the web app with the workspace lockfile and root install context. Set `PUBLIC_APP_URL=https://www.clips.gg/sloptogether` and the server secrets from `.env.example` in the child deployment only.
2. Apply migrations `001` through `019` in order to the existing Clips.gg project. Migration `018` creates the restricted `sloptogether_app` role, and migration `019` enables its login without granting broader privileges. Set its password through a secret manager and use that login for the app and worker. For Vercel, use the Supabase IPv4 transaction pooler with username `sloptogether_app.<project-ref>`; the direct database hostname is IPv6-only and is not resolvable from the Vercel runtime. Set `SLOPTOGETHER_DATABASE_SSL_CA` to Supabase's public `prod-ca-2021.crt` and retain certificate verification. Do not use a shared Clips.gg application role or a database superuser for the public runtime. Set `SLOPTOGETHER_USE_CLIPSGG_DATABASE=true` only for that configured shared-project connection. The server checks both the pooler host and the schema-scoped username.
   Supabase currently reports RLS disabled on the 44 SlopTogether tables. The `sloptogether` schema has no `USAGE` grant for `anon` or `authenticated`, so those API roles cannot reach the tables through those grants. Keep it private; verify actual exposed-schema configuration before any API exposure. Do not grant public schema access or enable RLS alone; first define the intended role policies, or RLS will deny the runtime's queries.
3. The private `sloptogether-media` bucket and `sloptogether-upload-gateway` Worker are deployed. The Worker is bound only to that bucket; `uploads.clips.gg` is its Cloudflare-managed custom domain, and its `workers.dev` address and the bucket's public `r2.dev` domain are disabled. Gateway/ticket secrets, `R2_ACCOUNT_ID`, `R2_BUCKET_NAME`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` are configured in Vercel Production; health reports `objectStorageMode=cloudflare_r2`. The R2 API token is restricted to `sloptogether-media`; do not reuse the Clips.gg media bucket or credentials. This health check proves configuration presence only. Still verify a real signed PUT, ticket completion, private object read/range and media publication through `uploads.clips.gg`; deploy and supervise `npm run media-worker` with the schema-scoped database login, R2 and moderation credentials. Keep CORS limited to `https://www.clips.gg` and allow only the exact R2/gateway upload hosts in workers.
4. The `SlopTogether Web` OAuth app and Extension `0.0.1` are registered with callback `https://www.clips.gg/sloptogether/api/v1/auth/twitch/callback`. OAuth client credentials and the Extension signing secret are in Vercel Production; health reports `twitchOAuth=true`. The Extension remains in Local Test with asset base `https://www.clips.gg/sloptogether/extension/`; Bits support is off. The user explicitly skipped the Twitch consent test, so no account session, first channel, EventSub delivery or live Extension session is qualified. Do not retry account consent until the user opts in. Twitch must approve the Extension and enable its Bits product catalog before those features can accept real transactions.
   For EventSub secret rotation, set `TWITCH_EVENTSUB_SECRET_PREVIOUS` while changing `TWITCH_EVENTSUB_SECRET`, then save the enabled subscriber/chat settings for each channel so the app re-registers that channel's subscriptions. Remove the previous secret only after all enabled channels have been resynchronized.
   For Extension Bits, configure the fixed SKU products in Twitch's Monetization catalog, register `extension.bits_transaction.create` with `extension_client_id` equal to `TWITCH_EXTENSION_CLIENT_ID`, and use an app access token created with that Extension client ID/secret. After applying migrations 011–013, create/recreate the webhook subscription so callback verification records its active state; revocation removes Bits products from the Extension even if static gates were left enabled. Configure `SLOPTOGETHER_BITS_RECONCILE_SECRET` and the exact internal endpoint URL identically in the web app and supervised media worker; the media worker must also receive `PUBLIC_APP_URL` so it can verify the reconciliation URL origin. The worker reconciles delayed receipts against Twitch's authoritative transaction API and marks aged missing transactions `receipt_unverified` for explicit support reconciliation without claiming authoritative payment; this route accepts only the shared server secret. Set `SLOPTOGETHER_BITS_EVENTSUB_READY=true` only after webhook verification and transaction lookup work; keep `SLOPTOGETHER_BITS_POLICY_APPROVED`, `SLOPTOGETHER_BITS_TURBO_ENABLED`, and `SLOPTOGETHER_BITS_DISPATCH_READY` false until the exact product/action has been approved and the server dispatcher is operational.
5. `SLOPTOGETHER_OPENAI_MODERATION_KEY` is configured in the production web server and health reports `openaiPreflight=true`; the production moderation request, latency and outage behavior still need an end-to-end acceptance check. It calls OpenAI's free text/image Moderation endpoint; missing or unavailable screening blocks new dispatch. Keep any paid `OPENAI_API_KEY` for story planning in the owner story worker only.
6. Optional Comfy Cloud prompt and start-frame generation is manual-only: a signed-in broadcaster or verified Twitch moderator must click the site button and confirm each paid request. Extensions, workers, story producers, cron jobs and background effects cannot start it. Configure a paid Comfy Cloud API key as `SLOPTOGETHER_COMFY_API_KEY`, the moderation key from step 5, separate gates `SLOPTOGETHER_COMFY_FRAME_GENERATION_ENABLED=true` and `SLOPTOGETHER_COMFY_PROMPT_GENERATION_ENABLED=true`, and a comma-separated `SLOPTOGETHER_COMFY_FRAME_GENERATION_CHANNEL_IDS` allowlist. The service allows one active or uncertain job per shared account, caps it at five requests per hour and each operator at three per hour, screens the brief before submission, validates and screens generated H3 prompts before filling the proposal, crops image outputs to the TrimH3 448×256 profile, and screens generated images before attaching them to the normal proposal form. Ambiguous provider submissions are marked uncertain and are never automatically retried; the uncertain row blocks further Comfy jobs for the shared key until an operator resolves it using the Comfy Cloud account UI or support. Frame prompts and provider job IDs expire after seven days through the supervised media worker's outbox cleanup, so keep that worker running. Keep the key out of the browser, media worker and Windows executable.
7. Run `npm run media-worker` as a supervised Node process with the same schema-scoped database login and R2 credentials restricted to the SlopTogether bucket. Install `ffprobe` and `ffmpeg`; the media worker uses `SLOPTOGETHER_OPENAI_MODERATION_KEY` for endpoint-frame screening. This process validates admitted MP4s, publishes approved base clips as HLS, creates a continuation boundary when the extracted frame passes screening, and cleans up staging uploads. For owner-generated scenes, configure a measured `SLOPTOGETHER_GENERATION_ATTEMPT_RESERVATION_USD` in the web server and set each channel's owner budget cap above the per-attempt reservation; either missing value intentionally prevents a scene from being appended. Subscriber interrupts use the separate `SLOPTOGETHER_SUBSCRIBER_ATTEMPT_RESERVATION_USD` and the same channel cap. Keep the owner's optional paid-planning `OPENAI_API_KEY` only in the story-producer process; without it, the worker uses its bounded template planner. Pair the story producer with an owner-scoped `story:write_future` key and run separate generation/upscale worker roles with role-scoped keys. Fal app credentials belong in Fal's secret store, not its image or deployment command. Keep serverless apps at zero minimum concurrency and a one-runner maximum; the runtime supervisor stops a session at eight hours, with idle scale-down as a fallback.
   For the paid Turbo path, configure `FAL_KEY` only in this supervised worker. Keep the four `SLOPTOGETHER_BITS_*` gates synchronized between the web app and media worker. Leave `TURBO_ENABLED`, `POLICY_APPROVED`, `EVENTSUB_READY`, and `DISPATCH_READY` false until the Twitch action is approved and live Fal private-output, budget, cancellation, uncertainty recovery and Postgres/R2 acceptance checks pass. The code submits a single Fal request, uses private expiring Fal CDN output, and sends the result through the existing quarantine and moderator-review pipeline. Live acceptance remains outstanding.
8. Add a signed Windows release only after building and validating the installer on Windows and measuring the claimed GPU profiles. The subpath and Cloudflare-R2 configuration are live; still verify path-preserving navigation, OAuth state-cookie delivery after explicit consent, that Clips.gg root cookies are not forwarded to the child, upload limits, real range playback, EventSub signature handling, moderation, and rollback of the host mount.

The current codebase supplies the child app, upload gateway, media validation/HLS publisher, worker APIs, Twitch OAuth/Extension source, Comfy prompt/frame paths and subscriber/Bits pipelines.
