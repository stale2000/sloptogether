## Configuration

1. Deploy the web app with the workspace lockfile and root install context. Set `PUBLIC_APP_URL=https://www.clips.gg/sloptogether` and the server secrets from `.env.example` in the child deployment only.
2. Apply migrations `001` through `023` in order to the existing Clips.gg project. Migration `018` creates the restricted `sloptogether_app` role, migration `019` enables its login, and migration `023_media_publisher_role.sql` creates a publisher role inheriting only the SlopTogether schema role. Provision that role's login and password separately in a secret manager; do not put credentials in migrations or source control. For Vercel and the publisher, use the Supabase IPv4 transaction pooler with project-scoped usernames `sloptogether_app.<project-ref>` and `sloptogether_publisher.<project-ref>` respectively; the direct database hostname is IPv6-only and is not resolvable from Vercel. Set `SLOPTOGETHER_DATABASE_SSL_CA` to the certificate downloaded from the project's Database → SSL Configuration page and retain certificate verification. Do not use a shared Clips.gg application role or a database superuser for the public runtime. Set `SLOPTOGETHER_USE_CLIPSGG_DATABASE=true` only for these configured connections. Each runtime validates the pooler host and its allowed schema-scoped login.
   Supabase currently reports RLS disabled on the 44 SlopTogether tables. The `sloptogether` schema has no `USAGE` grant for `anon` or `authenticated`, so those API roles cannot reach the tables through those grants. Keep it private; verify actual exposed-schema configuration before any API exposure. Do not grant public schema access or enable RLS alone; first define the intended role policies, or RLS will deny the runtime's queries.
3. The private `sloptogether-media` bucket and `sloptogether-upload-gateway` Worker are deployed. The Worker is bound only to that bucket; `uploads.clips.gg` is its Cloudflare-managed custom domain, and `workers.dev` plus public `r2.dev` access are disabled. `UPLOAD_TICKET_KEY` remains shared only by the web app and worker clients; `PUBLISHER_UPLOAD_TICKET_KEY` is a separate secret for publisher tickets. The production publisher uses the gateway and does not need direct R2 keys. Keep CORS limited to `https://www.clips.gg` and the Worker bound only to `sloptogether-media`.
4. The `SlopTogether Web` OAuth app and Extension `0.0.1` are registered with callback `https://www.clips.gg/sloptogether/api/v1/auth/twitch/callback`. OAuth client credentials and the Extension signing secret are in Vercel Production; health reports `twitchOAuth=true`. The refreshed Extension ZIP is in Hosted Test, with identity linking and `www.clips.gg` configured as a fetch domain, and is installed and active as Panel 1 on `stale2000`. In a real Twitch test, the linked broadcaster submitted proposal `72f330e8-0d1c-4e99-9063-f7c14594d47d` and cast a free vote; the panel showed one vote and the database confirmed one ballot. A separate viewer's consent/linking flow remains untested; live EventSub delivery is also unqualified.

   Bits support is enabled in the Extension's Local Test settings, but Twitch monetization onboarding is incomplete and the product catalog does not retain test SKUs yet. The Hosted Test flow is therefore not live. Keep broad enablement behind normal Twitch review of the actual product. Never describe Extension Bits as a donation. Free prompt participation remains available. Sources: [Twitch policy](https://dev.twitch.tv/docs/extensions/guidelines-and-policies/), [Twitch Bits examples](https://dev.twitch.tv/extensions/bits-extensions-to-try/), [Sound Alerts TTS](https://soundalerts.com/blog/new-feature-text-to-speech-alerts/).
